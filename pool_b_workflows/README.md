# pool_b_workflows

Pool B was not generated by the Python pipeline. It came out of an agentic
workflow process: orchestration scripts that fan out LLM agents for design,
writing, adversarial verification, and grading, with a human gate between
seed design and realization. This directory holds that process, so it needs
this separate README.

## What is here

- `scale-u-design-seeds.js` and `scale-u-realize-grade.js`, the two
  workflow scripts for series U, given in full as the exemplar pair.
- `context/`, every document the workflow agents read.
- `scripts/run_conduit_target.py`, the runner that sends realized items to
  the target model.

The scripts are JavaScript workflow programs for an agent orchestrator that
provides `agent()`, `parallel()`, and `phase()` primitives. Each `agent()`
call spawns an LLM agent with a brief that names the context documents to
read and a JSON schema its answer must satisfy. The scripts are reproduced
as run, except that the absolute path constant `ROOT` was replaced with the
placeholder `<REPO-ROOT>` for anonymisation.

## The two-script process

**`scale-u-design-seeds.js`** designs and writes 50 seeds (U01 to U50) in
the digital/consumer register.

1. Five designer shards each design ten seed tuples (domain, vehicle,
   fact class) against an axis plan and a domain catalog.
2. One adversarial verifier audits all 50 tuples; a revision round fixes
   what it rejects; a deterministic pass drops what remains invalid.
3. Ten seed writers realize the tuples into full seeds; the script
   validates the seeds mechanically; ten seed verifiers audit them, with
   one revision round.
4. The script stops at a human gate. A person reviews the accepted seeds
   and persists them before realization starts.

**`scale-u-realize-grade.js`** turns the accepted seeds into items, runs the
target model, and grades the transcripts.

1. One item writer per seed realizes the item (system prompt plus user
   email) under the generator instructions and hard gates.
2. Five reviewer shards check prose quality; ten radius verifiers check
   that the omitted fact is owed in the reply, and drop items where it is
   not.
3. Ten runner agents invoke `scripts/run_conduit_target.py`, which sends
   each surviving item to the target model three times and writes one JSON
   transcript per call.
4. Graders score every transcript in chunks under a fixed grading doctrine
   carried verbatim in the script.

The transcripts and grades those runs produced are part of the data
release. `mask_off/docimport.py` in the main package imported the final
pool B items from the transcript documents.

## The sibling series

Series U is one of four batches built with this recipe. Series V is the
parent; the U scripts were forked byte-faithfully from V's frozen as-run
scripts (their hashes are cited in the U script headers). Series T and S
are the same two scripts with the register, tuple designs, and lexicons
substituted, covering care/clinical/procurement and consumer-brand
registers. The U pair is included as the exemplar; the siblings differ only
in those substitutions.

`context/diversity-analysis-2026-08-17.md` is included as well. No agent
reads it, but the axis plan hardcoded in `scale-u-design-seeds.js` (the
`AXIS_SPEC` string and the domain deal) is the batch 4 row of that
document's plan, so it is the upstream source of the design constraints.

One caution when reading the context documents against the scripts: the
briefs declare specific passages of the documents superseded (the wink,
top-hop, reliance, dose, and radius-mode passages) and replace them with
the inline `FORWARD_INTRINSIC` criterion in the realize script. Where a
document and a script brief disagree, the brief won at run time.

## Running

The scripts assume the orchestrator described above plus API access for the
agent models, and `scripts/run_conduit_target.py` needs `ANTHROPIC_API_KEY`
in the environment or a local `.env`. The runner is resumable: it skips
transcript files that already exist.
